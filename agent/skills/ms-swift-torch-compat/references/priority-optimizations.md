# ms-swift CUDA 优化与开关验收矩阵

本轮只验证 ms-swift 经 JTorch 在真实 CUDA 上的公开训练、推理、算法与开关。CPU 仅可作为独立原生 PyTorch oracle 的设备对照之外的历史材料；不开发 CPU 适配，也不运行 CPU 全量或 smoke 门禁。先选一个可运行的小型 causal LM、固定数据和公开入口；只有 MoE、多模态或模型专属能力才换最小适用模型。复用同一源码、设备和执行路径的已有证据，不重复已完成实验。

## 归属与优先级

从公开入口追踪实际调用。经过 JTorch 的功能列为必验或条件验；完全由 vLLM、SGLang、Unsloth、Megatron 等独立引擎执行的路径记录为外部归属，不记为 JTorch 通过。小模型不支持的模型专属开关写“不适用”并说明原因；缺硬件、依赖或证据写“未验证”。相互独立的参数不做全组合笛卡尔积。

| 优先级 | 共享执行路径与代表开关 | 最小验收 |
| --- | --- | --- |
| 必验：训练状态 | AdamW/基础 scheduler、梯度累积与裁剪、checkpoint 新进程恢复、LoRA 加载与合并 | 公开训练入口实际更新；loss 有限且整体下降；保存恢复连续；无 fallback；记录设备峰值显存 |
| 必验：精度与注意力 | BF16/FP16（硬件适用者）、`attn_impl` 的 SDPA/可用后端、`gradient_checkpointing` | 关闭/开启都真实进入对应路径；dtype/梯度正确；训练 loss 整体下降；记录同配置设备峰值显存 |
| 必验：数据与损失 | `packing`、`padding_free`（适用者）、loss mask/token 权重 | 样本边界与标签正确，无跨样本泄漏；loss 整体下降；记录设备峰值 |
| 必验：偏好/RL | DPO 基础损失与一种改变公式的代表变体；GRPO 奖励缩放、KL/裁剪、生成组大小/动态采样；GKD 本地教师与混合损失 | 开关被真实读取并改变预期行为；奖励/掩码/梯度有限，训练 loss 有可解释的整体趋势；记录设备峰值。RL 目标不保证逐步单调 |
| 条件验：额外优化 | GaLore/Muon、Liger、FlashAttention、量化训练、FSDP/ZeRO/Megatron、MoE 融合、投机解码 | 只在公开路径、依赖、模型和 CUDA 设备适用时执行；报告实际引擎归属、正确性、无 fallback 和设备峰值。显存优化须同口径对照 |

每个开关只记录代表性的关闭/开启对照：完整源码与依赖 SHA、入口命令、模型/数据、设备和卡数、实际调用路径、loss 或推理输出、fallback、设备峰值显存与证据路径。训练跑几步不自动等于收敛；用同一小样本延长轨迹观察有限且整体下降，不要求每步单调。推理检查输出、logits/KV cache 或接受率中的适用指标。计时、吞吐和速度比不是本轮验收项；历史性能报告只按其原基线解释。训练日志里的 `memory(GiB)` 不得替代 NVML 设备峰值。

发现缺陷时按根因归属修 JTorch core、torch compat 或 CUDA 后端；不在每个算法旁添加私有补丁。同一根因最多五次有区别的尝试，仍失败则记录并转下一项。代码和技能按功能单位分别提交，只暂存当前任务文件，验证后快进推送个人分支。
