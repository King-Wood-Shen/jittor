# 主要优化与开关的验收路径

本页用于 ms-swift 经 JTorch 在 CUDA/Ascend 上的本轮验证。先用同一个可运行的小型 causal LM、固定数据和配置完成公开入口基线；只有 MoE、多模态或模型专属功能确实需要时才换最小适用模型。复用相同源码、设备和执行路径的已有证据，不按参数名穷举，也不重复已完成实验。

## 先决定归属和优先级

每项先从公开入口追踪实际调用：经过 JTorch 的功能列为必验或条件验；由 vLLM、SGLang、Unsloth、Megatron 等独立引擎完全执行的路径记录为外部归属，不能写成 JTorch 通过。小模型不支持的模型专属开关写“不适用（附原因）”；缺硬件、依赖或证据写“未验证”。相互独立的参数不做全组合笛卡尔积。

| 优先级 | 共享执行路径与代表开关 | 最小验收 |
| --- | --- | --- |
| 必验：训练状态 | AdamW/基础 scheduler、梯度累积与裁剪、checkpoint 新进程恢复、LoRA 加载与合并 | 公开训练入口实际更新；有限且整体下降的 loss；保存恢复连续；无 fallback；记录设备峰值显存 |
| 必验：精度与注意力 | BF16/FP16（硬件适用者）、`attn_impl` 的 SDPA/可用后端、`gradient_checkpointing` | 开关前后实际进入对应路径；dtype/梯度正确；训练 loss 整体下降；记录同配置峰值显存 |
| 必验：数据与损失 | `packing`、`padding_free`（适用者）、loss mask/token 权重 | 样本边界和标签正确、无跨样本泄漏；loss 整体下降；记录峰值显存 |
| 必验：偏好/RL | DPO 基础损失与一种改变公式的代表变体；GRPO 的奖励缩放、KL/裁剪、生成组大小/动态采样；GKD 本地教师与混合损失 | 开关被真实读取并改变预期行为；奖励/掩码/梯度有限，训练 loss 有可解释的整体趋势；记录峰值显存。RL 目标不保证逐步单调，不能只看单个 loss 值判定通过 |
| 条件验：额外优化 | GaLore/Muon、Liger、FlashAttention、量化训练、FSDP/ZeRO/Megatron、MoE 融合、投机解码 | 仅在公开路径、依赖、模型和设备均适用时执行；报告实际引擎归属、正确性、无 fallback 与峰值显存。声称节省显存时必须同口径对照 |

每个开关只记录代表性的关闭/开启对照：完整源码与依赖 SHA、入口命令、模型/数据、设备和卡数、实际调用路径、loss 或推理输出、fallback、设备峰值显存与日志位置。训练的“跑通几步”不自动等于收敛；延长同一小样本训练以判断有限且整体下降，不要求每步单调。推理没有 loss，检查输出、logits/KV cache 或接受率中适用的结果。计时、吞吐、速度比不作为本轮验收项；历史性能报告仅按原 SHA 保留。`memory(GiB)` 训练日志字段若不是实际设备峰值，不得代替 CUDA/NPU 峰值证据。

发现缺陷时按根因归属修 JTorch core、torch compat 或设备后端；不要在每个算法旁加私有补丁。同一根因最多五次有区别的尝试，仍失败则记录并转下一项。代码和 Skill 按功能单位分别提交；读取 `../github-collaboration-commit/SKILL.md`，只暂存本次文件，验证后快进推送自己的分支，不推送未完成的并行工作树改动。
