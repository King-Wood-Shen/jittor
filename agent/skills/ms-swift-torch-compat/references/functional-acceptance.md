# DeepSeek MoE × ms-swift 当前功能验收合同

## 三个方面分别交付

| 方面 | 实际范围 | 需要的结果 |
| --- | --- | --- |
| 算法 | 原Qwen清单的PT/SFT/DPO/ORPO/SimPO/KTO/CPO/RM/PPO/GRPO/GKD | 完整目标模型、真实ms-swift公开入口、目标对应的有效收敛、正确的训练参数与真机执行；多rank优先 |
| 优化 | 原清单中实际用到的优化器/状态、梯度累积、裁剪、精度训练路径及GaLore/Liger/BNB等配置的适用项 | 优化路径实际启用，有真实更新、状态/设备正确且训练收敛；特殊方法不支持当前冻结LoRA时明确原因和独立配置，不能混入基准验收 |
| 开关 | 原清单中的checkpoint、packing/padding-free、分布式同步、保存恢复等影响ms-swift训练的开关 | 证明开关确实生效，在对应开/关或指定配置下完成训练/恢复；共享正常结果复用，只做差异验证 |

优化器和开关从实际Qwen清单恢复，不发明全排列，也不把历史登记/准备状态当通过。用户当前没有要求为无关框架建立新覆盖矩阵。

## 本轮做什么、不做什么

- 做：L1公开入口/前向、L3真实有效训练收敛、L5分配的CUDA/NPU真机执行及零fallback；多rank训练、checkpoint和新进程恢复语义。
- 不作为交付前置：L2逐元素Torch数值/梯度相等、严格不中断轨迹逐点相等、L4速度/显存性能比。资源峰值可为申请资源/OOM定位记录，但不作性能排名。
- 不放宽：NaN/Inf、没有梯度或参数更新、错误模型/目标、未使用申请设备、用单进程多卡代DDP、偷换随机/小模型、恢复状态缺失、吞异常或假日志。
- 必要的最小原生对照/数值诊断只服务于明确兼容故障，不能扩成新一轮广泛精度/权限扫表。

## 收敛证据

总控为每个训练目标预先记录简短判据：数据与目标、更新窗口、观察哪个指标、预计方向、异常条件。真实保留训练日志/曲线和参数更新，不使用“全跑完”“exit0”替代。

- PT/SFT通常看固定任务loss在足够更新下下降并趋稳；不要把偶然单步下降当收敛。
- 偏好/RM看目标loss及偏好/奖励指标，不强制所有目标loss都为正。
- PPO/GRPO/GKD按各自训练目标、奖励/约束或蒸馏指标判断；随机性允许波动，不要求每一步下降。奖励模型和teacher的实际身份仍必须正确。
- 参数范围须符合用户协议；默认LoRA首步A零梯度是合法初始化行为。后续要有真实有效更新，底座冻结不变。

训练窗口不是无限作业：按资源和当前证据提交有界工作；未收敛先分析数据/目标/优化/兼容错误，再决定延长或修复，不能循环同一失败实验。已通过的初始化、前向和有界更新结果复用。

## 多卡与恢复

首选实际两rank或用户指定多rank训练。完整16B每rank可按资源需要使用多卡放置；记录world size、rank-local布局、通信与梯度同步。复制式推理只能验证推理，不计多卡训练通过。

在训练实际边界保存后退出，用新进程恢复模型/adapter、优化器、scheduler、global step、每rank RNG和数据游标，确认接着有效训练并延续收敛。恢复状态正确与严格L2数值对拍是不同要求；本轮保留前者，不强求后者。

## 避免表面工作占主线

一个任务的主输出应是：真实实验结果、兼容补丁、定向验证、提交/推送，或精确外部阻塞。状态文件、权限检查、schema/哈希材料只服务于这些产物，不能成为反复循环的目标。

权限/沙箱失败由总控使用当前明确授权的正常启动路径解决；不反复跑同一探针。格式错就修实际请求；合法诊断不符合训练helper时由总控使用独立防重诊断路径，不要求本地代执行。仍保护他人作业、凭据、dirty和安全策略。

执行者完成/失败即反馈总控；总控方向/审核后接续原执行者。30分钟只是无事件兜底，不能把全组留在WAITING。
