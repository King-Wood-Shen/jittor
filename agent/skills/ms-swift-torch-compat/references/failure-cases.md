# 近期失败如何改变决定

这里只保留会改变下一步动作的反例。具体日志和作业号属于交接证据，不应变成适用于所有模型的硬编码规则。

| 已发生的失败 | 错误判断 | 正确动作 |
| --- | --- | --- |
| tmux 内 Python/Bash 活着，模型轮次已结束 | “Codex持续工作” | 核当前 SID/exec、近期成功命令、作业及未处理反馈，分别报告状态 |
| `turn.completed`/exit0，但工具成功0次，第一条命令 `bwrap pivot_root` 失败 | “巡检正常结束” | 包装器报告执行环境失败；总控按当前授权修环境/启动路径；不循环同一检查 |
| 执行者写 READY 后退出，总控固定睡30分钟 | “合理等待” | 反馈触发原总控立即审核、答复并续接；30分钟只作无事件兜底 |
| 正式16B helper 不认识最小诊断或角色/SimPO枚举 | “需要一直等manager” | 改准确请求；诊断真实标类、独立审核与防重提交，不冒充正式训练 |
| 复制 JIT cache 文件后迁移仍重编，导入提示尚未执行模型需新解释器 | “cache已热，训练失败可重跑” | 以实际命中/编译日志判断；仅文档化导入阶段有限换解释器，训练不重试 |
| 长 TMPDIR 导致 AF_UNIX path too long，后续出现EOF | “训练算法/通信失败” | 从首错修短而私有的临时目录，保留失败，修订精确输入/脚本后验证 |
| 完整模型加载后 `tr_loss -= tr_loss` 报叶子张量原地修改 | “加载已通过，所以训练通过”或关闭保护 | 比较原生/compat累计loss构造、detach及最早标记变化，最小红复现后修根因；保留原地检查 |
| deepcopy大模型失败，小score探针却全绿 | “探针通过，原错误已修” | 只认探针覆盖的条件；核实际上下文/设备/dtype/前序操作，补能区分根因的复现，不能无红证改源码 |
| 默认LoRA B=0造成A首步零梯度 | 强制A/B首步全非零或改初始化 | 保留默认协议，核后续梯度/实际更新；特殊初始化另列边界 |
| 单进程4GPU完整模型通过 | “双rank DDP及恢复通过” | 核真实world size、rank布局与新进程producer/consumer/control；不同轴独立验收 |
| Slurm节点MIXED、个人queue为空 | “有空GPU”或“个人额度已满” | 核AllocTRES、占用、请求和pending reason；合法任务正常排队，不空占/抢他人作业 |
| 日志尾部历史成功、状态还写RUNNING | “现在还在跑” | 报告采集时间并核真实终态；旧证据归档为原SHA/原job结果 |

不得从这些具体错误推断所有失败都需要同一补丁；每次保留首错和上下文，验证可反驳的根因假设。
