# Lab 容量恢复

只在具体运行的空间预检不足时执行清理。先记录运行键、目标文件系统、可用空间、预计产物峰值及安全余量；空间充足时直接继续作业。

## 可删除项的判据

逐项建立删除白名单。只纳入已核对内容及可恢复来源的重复副本，或确认无人引用、复验不再需要的临时产物。对每项记录路径、大小、运行键、用途、SHA-256 或等效校验、可恢复来源，以及判断无人引用的证据。检查正在运行的作业、其他代理的工作树和缓存使用情况。无法证明符合判据的文件不进入白名单。

保留唯一模型权重、必要 checkpoint、原始日志、结果矩阵、复验脚本、在用缓存，以及其他项目或代理的数据。不要把一次故障中的路径或删除命令写成通用规则。

## 执行与复检

执行前保存白名单和精确删除命令到本次运行的 `$JITTOR_LAB_ROOT/_state/<topic>/<run>/`；命令必须只指向白名单中的具体路径，不使用宽泛通配符。删除后记录实际释放量并重新检查同一文件系统的可用空间，再按原预检口径判断能否启动作业。若没有符合判据的可删项，保留现场并报告容量阻断及所需余量。
