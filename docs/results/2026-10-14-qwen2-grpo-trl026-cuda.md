## Profile and evidence

The profile used the local Qwen2-0.5B model, full FP32 tuning, SGD at `1e-5`, two completions, a one-row arithmetic prompt, deterministic local completion-length reward, and `trl==0.26.0`. No ms-swift source was edited.

Raw logs, arguments, input NPZ, per-step gradient summaries and checkpoints are under `$JITTOR_LAB_ROOT/_state/ms-swift-cuda/20261014-qwen2-grpo-trl026-full-v2/` (native 23117, shim 23248, comparison 23266). Worker jobs 23237 and 23245 respectively cold-built and then checked the same CUDA JIT cache with `JITTOR_NO_BUILD=1`; the second job changed no core `.so` hash, and both strict device checks had zero fallback. The shim CLI's start/end audit also recorded `cuda=1`, `fallback=0`.

## Same-process recovery subpath on the later baseline

On Jittor `7b090a68f5c04dfad4bc8a19718d0a6b110e18ca` and the same ms-swift checkout, run key `$JITTOR_LAB_ROOT/_state/ms-swift-cuda/20261014-qwen2-grpo-same-process-l3-v1/` used the real `python -m swift.cli.main rlhf --rlhf_type grpo` child process. A runtime audit hook stopped one trainer object after checkpoint 2 and then called `trainer.train(checkpoint-2)` on that same object through step 4; it did not edit ms-swift source. Worker preflight 23744 checked the isolated TRL dependency, native/shim trainer signatures, the existing strict CUDA no-build cache, a 1 MiB fsync write and capacity. Native job 23745 and strict shim job 23746 completed. Verifier 23751 inspected their checkpoint and audit payloads; the first verifier 23749 failed only because it treated each byte of the serialized 16-byte CUDA RNG tensor as a separate device, and worker inspection 23750 established the actual schema before correcting that read-only verifier.

Both sides recorded four training steps with all 290 trainable gradients present, finite and on CUDA. Losses across steps 1–4 were native `0, -0.00053778, -0.00107729, -0.00161469` and shim `0.00000143, -0.00080219, -0.00160822, -0.00241101`. After restoration, the scheduler advanced 2→4; both SGD checkpoints had two parameter groups and no per-parameter momentum state, as configured. The step-2 checkpoint's CPU and CUDA RNG bytes matched the restored runtime digests after forced perturbation. Of 290 saved model tensors, 252 native and 247 shim changed by checkpoint 4. The shim recorded `cuda=1 fallback=0`. This closes the checked same-process state and update subpath, while the one-row repeated dataset still leaves cursor restoration unverified. A distinct-sample control and resume are required before full L3 or formal L4 acceptance.
