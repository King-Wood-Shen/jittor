Same-process restoration and a distinguishable dataloader cursor are untested, so L3 is partial. L5 was not run for either profile.

A separate strict CUDA worker probe (23437) exposed a shared Torch compatibility defect: `torch.empty((), dtype=torch.int64, device='cpu').random_()` advanced CUDA RNG, left CPU RNG unchanged and produced a fractional float value. Native PyTorch advanced CPU RNG and returned an int64. The inherited Jittor Var method drew uniform fractions on the ambient device. The compatibility method now draws integer-valued chunks on the tensor's actual device, preserving CPU and CUDA RNG separation. Worker probe and directed regression job 23452 passed four tests for CPU int64/float32 and CUDA int64, with shim fallback zero. This repair did not cause the GKD RNG snapshot to change; the prior assertion was a verifier error, separate from the genuine `random_` defect. Worker job 23456 passed repository layout and Torch-mode structure (1404 passed, 8 skipped, 1023 subtests) on its CPU configuration; its 15-minute allocation expired during the subsequent core cold start. Core gate job 23481 passed on CPU (323 passed, 42 skipped, 1 xfailed) with a persistent isolated cache; strict CUDA method regression job 23452 passed independently.
